# Social Posts module — FAQ and common mistakes

## FAQ

### 1. Why did a task appear when I added a post?

You left the task field on **Create/link task automatically**. The app created a **Social Media**
task for the post: same title, same client, due on the scheduled date, assigned to the person who
added the post.

If the task already existed, the same field would have linked it instead of creating a new one.

### 2. Should I create the task first or the post first?

Either works.

- **Post first** — leave the task field on the default and the app creates the task.
- **Task first** — create the task on the **Tasks** board, then choose it in the post's task
  field.

The link is what matters, not the order.

### 3. The task field does not show the task I want. Why?

The list only shows tasks that are **not already linked to a post**. If the task you want is
missing, it is probably already linked to another post. Open that post, or create a separate
task for this work.

### 4. I created a post and it linked to an old task. Why?

When the task field is left on the default, the app first looks for an unlinked **Social Media**
task with the same client and the same title. If it finds one, it links it instead of creating a
duplicate. That is usually what you want. If it is not, open the task and correct the title, or
delete the post and add it again with a different title.

### 5. Which status should I use?

| Status | Use it when |
|---|---|
| **scheduled** | The post is planned and dated |
| **published** | The post is live |
| **pending** | You are waiting on approval, copy, creative, or access |
| **missed** | The planned date passed and the post did not go out |

Nothing changes **missed** automatically. Someone has to mark it, usually in the weekly review.

### 6. Does changing the post status change the task?

Yes.

| Post status | Task becomes |
|---|---|
| scheduled | in progress |
| published | done |
| pending | to do |
| missed | to do |

The reverse is also true: marking the task **Done** publishes the post, moving it to **In
progress** schedules it, and moving it to **To do** sets the post to **pending**.

### 7. Can one post have more than one task?

No. A post points at a single task. If the work needs a designer and a copywriter, create
separate tasks for those pieces and keep this task as the publishing owner.

### 8. Can two posts share one task?

Not from the interface. The task list hides tasks that are already linked to a post. If two
posts really are one piece of work, they should probably be one post or two tasks.

### 9. Can I change the caption or platform later?

The row's **Update** controls change the **status**, **publish date**, and **URL** only. The
caption, platform, title, and schedule date are set at creation.

If the caption is wrong, delete the post and add it again, or record the correction as a note on
the linked task.

### 10. Why does the dashboard count differ from the board?

The chips and the dashboard both count the current view. When you filter to one client, the
chips count that client's posts. Clear the filter to see the full picture.

### 11. What happens when I delete a post?

The post is removed. The linked task is **kept**, and the activity log records that the post was
deleted and the task was retained.

Use **Delete** for mistakes. For a post that simply did not go out, mark it **missed** so the
history stays readable.

### 12. Who can see which posts?

Owners see every client. Employees see posts for clients they are assigned to, plus clients where
they hold a task. If a post seems to be missing, check the client assignment on the **Clients**
page.

### 13. Where does the post appear outside this page?

- **Tasks** — the linked task card shows the Social Post under **Linked records**.
- **My Work** — the task appears in the assignee's queue.
- **Dashboard** — the **Social post status** block counts posts and links to the filtered view.
- **Clients** — the client page lists the client's posts with a **Manage** link.

### 14. Is this connected to Feedback?

Not directly. If a client gives feedback on a post, log it in **Communications** or **Feedback**.
The feedback becomes its own record with its own task. The post stays the publishing record.

## Common mistakes

| Mistake | Better habit |
|---|---|
| Typing the whole brief into the caption | Keep the caption as the real caption; put instructions in the task description or a note |
| Creating a post for work that is not agreed yet | Use **pending** until the client approves |
| Leaving an old **scheduled** date after the post slipped | Change it to **pending** or **missed** the same day |
| Creating a second post because the first one is “old” | Update the status and publish date on the same post |
| Adding a post with no client | Choose the client first; the task needs a client too |
| Publishing in Social Posts and then marking the task Done again | The task already moved to Done — check it before editing |
| Deleting a post to “clean up” | Mark it **missed** or **pending**; delete only real mistakes |
| Linking a post to a task for a different client | Pick the task that belongs to the same client; linking moves the task to the post's client |

## One-line rules for the team

1. **The post is the publishing record.**
2. **The task is the work record.**
3. **Link an existing task instead of duplicating it.**
4. **Keep the status honest — especially when a post slips.**
5. **Publish once. Both records update.**
