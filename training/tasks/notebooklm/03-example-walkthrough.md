# Tasks module — example walkthrough

## The scenario

Solhaus has asked for a **Diwali Campaign Reel**. The Social Media Executive is responsible for it.

In the demo data, this is already captured as one task:

| Field | Value |
|---|---|
| Task | Solhaus Diwali Campaign Reel |
| Client | Solhaus |
| Assigned to | Social Media Executive |
| Category | Social Media |
| Status | In progress |
| Due date | 22 November 2026 |
| Linked Social Post | Solhaus Diwali Campaign Reel — scheduled |
| Linked Communication | Solhaus asked to highlight the Diwali offer end date — pending |

The task, the post, and the communication are three views of **the same work**. They are not three separate projects.

## Walkthrough

### 1. Find the work

Open **Tasks**. The board lists every client’s work. Use the filters to choose:

- Client: **Solhaus**
- Category: **Social Media**
- Status: **In progress**

Click **Apply filters**. Only the matching tasks remain.

This is how a busy owner answers: “What social work is still in progress for Solhaus?”

### 2. Open the task

Open **Solhaus Diwali Campaign Reel**.

The card shows:

- **Social Media Executive** owns it.
- It belongs to **Solhaus**.
- It is a **Social Media** task.
- It is due on **22 November**.
- The status is **In progress**.
- **Linked records** shows the Social Post and the Client Communication.

### 3. See the connection

The same task appears in three places:

- **Tasks** — the work and its owner.
- **Social Posts** — the Instagram post and its publishing status.
- **Communications** — the client’s request and the response status.

Clicking a linked record opens that module with the same task.

### 4. Move the work forward

When the reel is finished:

1. Change the task status to **Done**.
2. Click **Update**.

The app immediately:

- Marks the task **Done**.
- Marks the Social Post **Published**.
- Marks the linked Communication **Responded**.
- Adds “Status moved from in_progress to done” to the task history.
- Adds the update to the client timeline.

Nobody needs to open Social Posts and change the status a second time.

### 5. Review the history

The **Activity history** shows who changed what and when. The client page shows the same event in the full Solhaus timeline, next to meetings, feedback, and other tasks.

This is the audit trail the owner uses in a weekly review.

## What to say in the video

> “This is one task, not three. When the Social Media Executive marks the reel done, the Social Post is published and the client communication is marked responded. The owner can see the same update on the client timeline.”

## Second example: when the record already exists

Sometimes the post is created first in **Social Posts**. In that case:

1. Open **Tasks**.
2. Create a task called **Solhaus Festive Carousel**.
3. Choose **Social Media** as the category.
4. Choose **Solhaus** as the client.
5. Instead of letting the app create a new post, choose the existing carousel in **Link an existing module record**.
6. Create the task.

The post is linked, not duplicated. The same pattern works for feedback, communications, blogger assignments, and meetings.
