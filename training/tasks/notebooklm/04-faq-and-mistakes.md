# Tasks module — FAQ and common mistakes

## FAQ

### 1. Why did a Social Post appear when I created a task?

Because you chose **Social Media** as the category and a client. The task is the parent record; the Social Post is the module record created for it. Create the task once, and the app creates the connected record.

### 2. I created a task, but no module record appeared. Why?

Two common reasons:

- The task has **no client**. Automatic module creation needs a client.
- The category is **Design, Strategy, Operations, or Other**. These categories do not create module records.

You can still update the task, assign it, and track it on the board.

### 3. Will it create a duplicate post if the post already exists?

No. The app first looks for an existing unlinked record that matches the task. If it finds one, it links it. You can also choose **Link an existing module record** yourself.

### 4. How do I connect an existing post to a task?

Open the task, use **Link an unlinked record…**, choose the post, and click **Link**. Or choose the record while creating the task.

### 5. What happens when I mark a task Done?

The task becomes Done and the linked module record follows the status mapping. For a Social Media task, the Social Post becomes Published. For Feedback, it becomes Implemented. For Client Communication, Responded. For Blogger Collaboration, Completed. For a Meeting, Completed.

The activity history and client timeline both record the change.

### 6. Why did the post status change when I only updated the task?

Because the task is the source of truth. The linked record is not a separate project; it is the same activity shown in another module.

### 7. Can I reassign a task?

Yes. Change **Assigned to** in the task card and click **Update**. The new owner sees it in **My Work**, and the dashboard workload reflects the change.

### 8. Can I change the due date after creating the task?

Yes. Change the date in the task card and click **Update**. Overdue highlighting and the dashboard counts update on the next page load.

### 9. What happens if I delete a task?

The task is deleted, but linked module records are kept and unlinked. A published post or a completed meeting is not destroyed just because the task was removed.

### 10. Who can see the task board?

Everyone who can open **Tasks** sees the shared board. Employees use **My Work** for their personal queue. The **Team** page is owner-only.

### 11. Where do I see my own tasks?

Open **My Work** in the top navigation. It lists tasks assigned to you, your due dates, and your activity notes.

### 12. Why does a task say “Created from Client Meeting” or “Follow-up of …”?

Those labels show where the task came from. A meeting can create a follow-up task, and that task stays connected to the meeting that produced it.

## Common mistakes

| Mistake | Better habit |
|---|---|
| Creating a new post when one already exists | Choose **Link an existing module record** |
| Updating the post status instead of the task | Update the task; the post follows |
| Creating a task with no client and expecting a module record | Choose the client first |
| Writing a note like “done” | Say what changed: “Reel exported and scheduled for 22 Nov” |
| Deleting a task to remove work that already happened | Keep the task and mark it Done; linked records are preserved either way |
| Using the wrong category | Pick the category that matches the work, not the person |

## One-line rules for the team

1. **Create it once as a task.**
2. **Let the category connect the module.**
3. **Update the task, not five places.**
4. **Add a note when the status changes.**
5. **Link existing work instead of duplicating it.**
