# Tasks module — module brief

## What this module is

Tasks is the single place where client work begins. Every request, idea, campaign, design, meeting follow-up, or client message can be captured as one task. The task then connects to the module record that does the actual work — a social post, feedback item, communication, blogger assignment, or meeting.

Think of it as:

> **Create once → connect everywhere → update everywhere.**

## Who uses it

| Person | How they use Tasks |
|---|---|
| Owner | Creates work, assigns owners, sets deadlines, reviews the whole board, checks overdue work |
| Social Media Executive | Creates and updates social tasks, checks the linked post, marks work done |
| Designer | Finds design work, updates status and due date, adds progress notes |
| Account / client team | Logs client communication, feedback, meetings, and follow-ups |
| Everyone | Uses **My Work** for their personal queue and **Tasks** for the shared board |

## What you can do

- Create a task with a title, owner, category, client, due date, status, and description.
- Filter the board by client, assignee, category, or status.
- Assign or reassign a task to any active team member.
- Update status, category, and due date from the task card.
- Add progress notes and blockers to the activity history.
- See every linked module record on the task.
- Link an existing post, feedback item, communication, blogger assignment, or meeting instead of creating a duplicate.
- Open the full client activity timeline from the client page.

## The task fields

| Field | What it means |
|---|---|
| Title | The work, written as an action (“Solhaus Diwali Campaign Reel”) |
| Assigned to | The person responsible for moving it forward |
| Category | The type of work; this decides whether a module record is created |
| Client | The account the work belongs to; required for automatic module creation |
| Due date | When the work is expected; overdue tasks are highlighted |
| Status | To do, In progress, or Done |
| Blogger | Optional, for blogger collaboration tasks |
| Meeting / activity date | Optional, for meeting-related work |
| Description | Instructions, context, or the client request |
| Linked record | An existing module record to connect instead of creating a new one |

## Categories and what they connect

| Category | Connected module |
|---|---|
| Social Media | Social Posts |
| Client Feedback | Feedback |
| Client Communication | Communications |
| Blogger Collaboration | Bloggers |
| Meeting / Prep | Meetings |
| Design | No module record |
| Strategy | No module record |
| Operations | No module record |
| Other | No module record |

**Important:** automatic module creation needs a client. If the task has no client, the task is still created, but no module record is created.

## Status behaviour

The task is the source of truth. When you move it, the linked record follows.

| Task status | Social Post | Feedback | Communication | Blogger | Meeting |
|---|---|---|---|---|---|
| To do | Pending | Pending | Pending | Assigned / not started | Upcoming |
| In progress | Scheduled | Requires discussion | Pending | In progress | Upcoming |
| Done | Published | Implemented | Responded | Completed | Completed |

The exact wording in the app always wins. The principle is simple: **one status update, everywhere it matters.**

## Rules that prevent duplicate work

- The app checks for an existing linked record before creating a new one.
- The same record cannot be linked to two tasks.
- Linking an existing record is always safer than creating a second copy.
- Deleting a task does **not** delete the linked post, feedback, communication, blogger assignment, or meeting. They are unlinked and kept.

## Where to find things

| Page | What it shows |
|---|---|
| Tasks | The shared task board, filters, create form, and linked records |
| My Work | Your own tasks, due dates, updates, and assigned client work |

## Three habits to teach

1. **Create the task first**, then let the category create the connected record.
2. **Update the task**, not five different modules.
3. **Add a short note** whenever the status changes, so the history explains why.
